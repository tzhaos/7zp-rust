# v0.3.0 验证记录

[English](verification-v0.3.0.md) · [使用与开发说明](reference.zh.md)

日期：2026 年 9 月 24 日，Windows x64。本轮没有新增测试或烟雾测试代码，只在当前工作区和 Cardo 子模块实施。

## 构建与包检查

- 各抽取批次均在提交前完成 Cardo 构建和 `tools/build.ps1`。
- 两个 workspace 最终版本为 0.3.0，GPUI Kit 保持 0.6.1；Cardo Desk 独立应用版本为 0.1.0。
- `cargo check --workspace`、runtime/app 最小 feature、Cardo 全 feature release、独立模板默认及 update 配置通过。
- `tools/build.ps1 -ReleaseRepository tzhaos/7zp-rust -Package All` 生成安装包、绿色包和校验清单。
- ZIP 完整性检查通过，16 个文件与更新白名单完全一致，包含 `Cardo-dependencies-LICENSE.txt`。两个包的 SHA-256 与 `SHA256SUMS.txt` 一致。
- 三种语言键和参数一致：产品 489 条、Cardo runtime 21 条、模板 21 条。
- Cardo crate 与模板源码无产品身份和 `p7z-*` 依赖。P7Z 已删除被替代的原生管道、系统图标、更新及重复绘制实现；剩余包装只提供产品标签、图标、尺寸和策略。

## 实际运行观察

- 简体中文主页和应用设置页正常显示；原生新建表单多次打开，Escape、取消、Alt+F4 均关闭窗口，主窗口右上角原生关闭按钮退出进程。
- 英文 SHA-256 报告处理项目 LICENSE：1,067 字节，哈希为 `7263f93d0b8e3d71aa30c14f9626566cecb55c92ef95d48318e9d7664f257086`，与系统工具一致。
- 第二次启动将 `--extract-here` 与本地验收 ZIP 交给现有实例，退出码为 0；报告打开时请求排队，关闭后继续执行。
- 解压文件与源文件哈希一致；冲突选择重命名生成另一个文件。解压表单输入在自己的原生窗口创建并取得焦点。
- 全部跳过同名文件实际显示英文 Toast；正常解压完成也显示 Toast，随后自动消失，没有必须关闭的结果弹窗。未精确测量过期时长或替换竞态。
- 繁体中文主页与应用设置页已观察，语言通过启动参数选择，没有保存产品偏好。
- Cardo Desk 独立完成同一文件哈希、保存简体中文和深色设置、显示并过期保存通知、拒绝外部 TOML 修改且未覆盖文件，并接收第二实例请求。

验收文件位于不进版本控制的 `.tools/acceptance-v030`；打开 ZIP 会产生正常历史记录。模板使用自己的 `%LOCALAPPDATA%\cardo-desk`，不使用产品数据目录。

## 未验证场景

强制原生开窗失败、全部焦点与宿主释放竞态、Toast 拖动和视口边界、快捷键冲突/禁用/编辑组合、字体错误展示、设置保存中断、任务取消期间关闭、完整菜单与选择矩阵、全部主题/语言/DPI 组合和多显示器定位仍有运行缺口。

更新取消、校验失败、安装版/绿色版应用、中断恢复和回滚已检查源码，但**本版未在隔离安装目录实际执行**。未用用户安装中的程序或注册信息进行更新验收。生成安装包不等于验证安装或更新。

现有 GPUI 窗口与无障碍日志警告仍是已知诊断限制。完整 7-Zip File Manager 功能尚未覆盖，详见开发说明。本地验证后推送 tag，不等待或复核远端构建。
