# UI Development

The file manager is a virtual Cargo workspace. Every package lives under `crates/` and is named `cardo-7zp-*`. `crates/cardo-7zp-app` is the process entry and still produces `7zplus.exe`. `crates/cardo-7zp-engine` runs the bundled `7z.exe`. `crates/cardo-7zp-requests` holds the current folder and the background requests submitted by the window; it is not the executable. `crates/cardo-7zp-commands` is the shared Explorer-menu contract, and `crates/cardo-7zp-explorer` is the right-click DLL. Windows file opening, registry, and single-instance code stay in `crates/cardo-7zp-platform`. Settings and localization stay in `crates/cardo-7zp-core`. `crates/cardo-7zp-ui` holds actions, views, dialogs, components, and theme. The theme module applies a supplied theme and does not open settings files.

The start page is implemented in `crates/cardo-7zp-ui/src/views/home.rs`; file and history rows are in `views/files.rs`, and native window chrome is in `views/titlebar.rs`. Shared dimensions live in `crates/cardo-7zp-ui/src/theme/metrics.rs`, with dedicated `home` and `titlebar` groups. Command and input height 32, icon button size 30, radii 4 / 12 / 10, toolbar artwork 48, tool height 80, and tool width 66–72 are defined once in that module and used by the shared controls.

The start page uses the same `Command::Open` and `Command::Create` dispatch as the menu bar. History keeps its existing open, remove, and clicked-target context-menu behavior. The title-bar grip uses GPUI's `WindowControlArea::Drag` and does not introduce a separate mouse-drag state machine.

Toolbar collapse uses one shared `toolbar-expand` transition in `views/toolbar.rs`. The current page tool keeps a full slot, so changing pages does not resize the group or move the collapse button. The settings title is outside the sliding layer; that layer is absolutely positioned and clipped, so the slide cannot reflow the title.

Dropdown menus use `DropdownMenu::dropdown_menu`, which anchors to the trigger's top-left. Do not pass a right anchor and do not give a menu row a fixed width wider than `MENU_WIDTH` (280). Nested menus go through `submenu_style`: same width, 320px max height, scrolling inside the menu. The host measures a submenu together with the offset that places it beside the parent, so an oversized child is clamped away from the item that opened it.

Scrollable regions use `overflow_y_scrollbar` or `overflow_scrollbar` from `gpui_kit::component::scroll`. The thumb colors and `ScrollbarMode::Always` are applied in `theme.rs` and reach the scrollbar only through `Theme::sync_base`. The file list is a uniform list, so its thumb is a sibling `Scrollbar::vertical` on the same scroll handle rather than another scroll container. Search keeps the normal file row and does not pass a path as the row's second line. `file_icon` paints a short uppercase extension at the icon's bottom-right for files only.

Preferences, recent locations, language, theme, and the saved extract destination are persisted by `crates/cardo-7zp-core`. Appearance stores a comma-separated font stack and no longer stores a background or accent. The font menu lists families collected when the settings form is created. `theme::apply` keeps the first installed name as `Theme::font_family` and the rest as glyph fallbacks; an unlisted name is not passed through, because GPUI panics when laying out a missing family. The workspace layout and that settings split are in place.

No build or native runtime verification was performed for the start-page changes. Existing `bin/` files represent earlier source. Builds remain opt-in; no test code was added.
