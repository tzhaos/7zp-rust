# 7zplus

[English](README.md)

7zplus 是使用 Rust 编写的 Windows 原生压缩管理工具，界面基于 GPUI Kit 0.6.1，内置 7-Zip 26.03 引擎。浅色主题保留背景与内嵌白色内容面板，搭配大尺寸彩色工具栏图标。

## 功能

- 浏览压缩包和本地文件夹，搜索条目、排序、多选，以及访问最近位置。
- 创建 7z、ZIP、TAR、gzip、bzip2、xz 和 WIM 压缩包，按格式提供压缩、密码和分卷选项。
- 解压全部或选中条目，设置重名处理策略，检查完整性，以及取消后台任务。
- 对支持编辑的格式添加、重命名、删除条目，将条目复制或移出压缩包；读写 ZIP 注释。
- 使用 Windows 关联程序打开解压后的文件，计算校验和，生成或验证校验文件。
- 通过独立 Shell 扩展接入资源管理器，提供可选的用户级文件关联和单实例命令转发。
- 支持简体中文、繁体中文、英语，以及浅色和深色主题。外观页还可设置界面字体和字号。字体列出本机已安装的字体，也可以自己输入，多个字体用英文逗号分隔。

压缩操作使用内置引擎执行。使用外部程序打开条目后，对文件的后续修改不会自动写回压缩包。

## 构建与运行

环境要求：

- Windows x64，Rust 1.95.0，使用 `rust-toolchain.toml` 指定的 MSVC 目标。
- Visual Studio C++ Build Tools 和 Windows SDK。
- PowerShell；首次下载依赖时需要网络连接。

```powershell
./tools/build.ps1
./bin/7zplus.exe
```

脚本构建主程序与 Shell 扩展，下载并校验固定版本的 7-Zip 和 NSIS，生成以下产物：

```text
bin/
  7zplus.exe
  7-zip-plus.dll
  7zplus-amd64-installer.exe
  SHA256SUMS.txt
  runtime/7zip/
```

运行时应将 `runtime/7zip/` 保留在主程序旁。需要资源管理器集成时使用安装包。注册仅操作应用自有的用户级条目，不替换 Windows 默认压缩文件关联。

构建时传入 `-ReleaseRepository owner/repo` 可启用 GitHub 发布检查。用户配置保存在 `%LOCALAPPDATA%\7zplus-rust`。

## 命令行

```text
7zplus.exe [--lang zh-CN|zh-TW|en-US] [路径 ...]
7zplus.exe --register [dll 路径]
7zplus.exe --unregister
7zplus.exe --prepare-install <安装目录>
```

后三项命令用于安装与维护。资源管理器右键和主程序共用的命令编号在 `crates/cardo-7zp-commands` 中。

常用快捷键按 7-Zip 文件管理器中已实现的命令对齐。`Enter` 打开当前项，`Shift+Enter` 在外部打开，`Ctrl+Page Down` 在内部打开文件夹或压缩包。`F2` 重命名，`F5` 复制，`F6` 移动压缩包条目，`Delete` 删除这些条目。`Ctrl+R` 刷新当前位置，`Backspace` 和 `Alt+Up` 进入上级，`Ctrl+A` 全选。`Ctrl+O` 打开压缩包，`Ctrl+L` 聚焦地址栏，`Ctrl+F` 搜索，`Alt+Left` 返回，`Alt+E` 打开解压选项，`Alt+T` 检查完整性，`F1` 打开 7zplus 自己的说明。其他快捷键显示在对应菜单中。

## 架构

| 目录 | 职责 |
| --- | --- |
| `crates/cardo-7zp-engine` | 调用随包的 `7z.exe`。负责列出压缩包、创建、编辑、注释、校验和与进度解析。不画窗口，也不写注册表。 |
| `crates/cardo-7zp-requests` | 当前文件夹，以及窗口提交的后台请求：打开、解压、创建、读取目录、检查更新。这不是可执行文件。 |
| `crates/cardo-7zp-platform` | Windows 文件打开与图标、单实例命令、注册表集成、邮件和安装维护。 |
| `crates/cardo-7zp-core` | 设置与本地化：首选项、外观、最近位置、语言、主题和保存的解压目标。 |
| `crates/cardo-7zp-ui/src/lib.rs` | 工作区状态、订阅、初始化，以及输入和焦点同步。 |
| `crates/cardo-7zp-ui/src/actions` | 任务生命周期、压缩操作与设置变更的工作区协调。 |
| `crates/cardo-7zp-ui/src/views` | 窗口框架、菜单栏、文件列表和设置页面组合。 |
| `crates/cardo-7zp-ui/src/dialogs` | 对话框组合、压缩包创建表单和错误呈现。 |
| `crates/cardo-7zp-ui/src/components` | 公共按钮、输入框、提示、导航、列表、设置行、图标和菜单样式。 |
| `crates/cardo-7zp-ui/src/theme.rs`、`crates/cardo-7zp-ui/src/theme` | 公共尺寸、语义色板和 GPUI 主题应用。主题模块只应用给定主题，不打开设置文件。 |
| `crates/cardo-7zp-app` | 进程入口。生成的程序名仍是 `7zplus`。 |
| `crates/cardo-7zp-commands` | 资源管理器右键和 `7zplus` 共用的命令、压缩格式编号，以及选中文件的数据。没有窗口，也不调用 `7z.exe`。 |
| `crates/cardo-7zp-explorer` | 资源管理器右键菜单的 DLL。它只写下一项请求，由 `7zplus.exe` 执行。安装后的文件名仍是 `7-zip-plus.dll`。 |
| `locales`、`assets` | 产品文案和嵌入式视觉资源。 |
| `tools`、`packaging` | 固定版本引擎准备、构建脚本和 NSIS 安装包。 |

UI 命令派发后台任务并处理结果；视图组合公共组件，不在渲染中执行文件、进程、网络或注册表操作。右键菜单保留点击目标和选择快照。产品文案维护在三份语言文件中，以语义键标识，禁止将翻译后的文字作为状态。

## 界面规范

共享控件使用 `crates/cardo-7zp-ui/src/components` 中的组件，公共尺寸在 `crates/cardo-7zp-ui/src/theme/metrics.rs` 修改，颜色由 `crates/cardo-7zp-ui/src/theme.rs` 的语义色板提供。

命令按钮和单行输入框高度为 32px，命令文字使用 GPUI Kit 的 12px `XSmall` 尺寸。图标按钮为 30px 正方形。控件圆角为 4px，主面板为 12px，无箭头提示为 10px。工具栏保留 48px 图标，按钮高度固定为 80px，宽度为 66-72px。图标按当前显示缩放栅格化，并先做两倍采样再缩小。页面工具的展开和收起共用一段约 180ms 的宽度动画，末段按固定速度走完，不再拖一段越来越慢的收尾。切换视图不改变这一组按钮的总宽度，收起按钮留在原地；子页面标题留在滑入内容的上方，滑入发生在标题下的裁剪区域里。动画遵循减少动态效果设置，帧跟随屏幕刷新。外观中的字体和字号作用于窗口、文件列表、起始页历史和设置标签。多个字体按英文逗号的顺序使用：第一个已安装的是主字体，其余已安装的用来补缺字。没有安装的名称会保留在输入框里，但不会交给排版。工具栏、状态栏和命令按钮仍使用这些固定尺寸。

起始页左侧放置 Logo 和名称，竖线右侧提供打开、新建入口和可滚动的历史记录。历史项上方显示文件名，下方显示目录。标题栏中央的淡色点阵标记原生窗口拖动区域。起始页和拖动标记的尺寸分别集中在公共尺寸模块的 `home`、`titlebar` 中。这些布局修改仅做源码和格式检查；原生渲染、拖动、显示缩放和小窗口表现仍需在明确要求构建后运行验证。

下拉菜单从按钮左上角展开。二级菜单与父菜单同为 280px，并在这个宽度里滚动；子项若比父菜单更宽，夹回窗口时就会离开打开它的那一项。路径改为截断，不再把菜单撑宽。此定位修改尚未在原生界面中验证。外观里可以隐藏工具栏大按钮下的文字。

对话框共用一个可移动窗口：标题栏可拖动，正文可滚动，操作放在底部横条。关闭、取消和 Esc 走同一条关闭路径。进度窗口没有关闭按钮，只能停止任务。窗口打不开时，同一内容退回居中的卡片。帮助是 7zplus 自己的说明，不再打开随引擎附带的 7-Zip 手册。这些窗口行为尚未在原生界面中验证。

内容超出的滚动区域显示滚动条。轨道透明，滑块使用次要文字色，悬停时改用正文色，圆角与控件相同；内容没有超出时不显示。文件列表的滑块盖在列表右侧。搜索过滤后的文件行与未搜索时相同，名称下不再附加路径。文件图标右下角标出最多四位的大写扩展名，文件夹没有这个标记。滚动条和扩展名标记尚未在原生界面中验证。

背景、内嵌内容面板和彩色工具栏图标共同构成界面特征。新增视图复用固定版本的 GPUI Kit API 和公共组件，资源来源记录在 [THIRD_PARTY.md](THIRD_PARTY.md)。正常构建直接使用已提交资源，不依赖 Node.js 或 Python；重生成品牌资源时，`tools/render-brand.cjs` 使用 Sharp，`tools/generate-icon.py` 使用 Pillow。

## 范围与验证

产品目标是覆盖 7-Zip 26.03 File Manager 的用户功能。当前源码仍为部分覆盖：

| 范围 | 当前能力与缺口 |
| --- | --- |
| 文件与编辑 | 文件菜单只保留已经可用、并且作用在当前项上的命令：打开、在内部打开、在外部打开、重命名、复制、移动、删除、属性、注释和校验和，最后是退出。复制、移动、重命名和删除仍只修改压缩包条目。编辑菜单负责全选、取消、反选和按当前项的类型选择。本地文件的复制或删除，以及集成查看器、编辑器，都不进入菜单。 |
| 查看与收藏 | 查看菜单可按名称、日期或大小排序，并提供上一级和刷新。文件夹与压缩包导航、搜索和列表排序仍然可用。图标布局、扁平视图、双栏和收藏不进入菜单。 |
| 压缩包 | 打开、新建、按格式重新打开、最近的压缩包、解压、完整性检查、另存、压缩包信息和关闭都在压缩包菜单。原先文件菜单里只负责回到文件页的那一项已去掉，工具栏仍可切换。 |
| 工具与选项 | 工具菜单打开已有的选项页。校验和仍在文件菜单。外观会保存字体和字号。字体可以写成英文逗号分隔的多个名称。快速解压可以在完成后关闭当前压缩包，这项默认关闭。解压遇到同名文件时再询问，而不是事先选定覆盖方式。基准测试及完整的上游选项尚未覆盖。 |
| 帮助 | 7zplus 自己的说明、应用信息及可选发布检查。帮助菜单不再打开随引擎附带的 7-Zip 手册。 |
| Windows 集成 | 已实现资源管理器命令、用户级注册、安装维护与单实例转发；仍需在不同 Windows 版本中验证。 |

这次分层已通过 `cargo check --workspace` 类型检查，尚未在原生界面中启动。工具栏收缩、焦点行为、显示缩放和多语言布局仍需运行确认。只在明确要求时构建，`bin/` 中已有产物不能作为当前源码的验证依据。
