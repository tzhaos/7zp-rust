# Project Rules

- After completing changes, proactively run tools/build.ps1 and resolve build failures before handing back the work. This standing user authorization includes rebuilding after fixes; do not ask the user to request or approve each build. Report build results separately from runtime verification.
- Do not add tests, smoke tests, or other test code.
- Keep implementations direct. Do not add speculative compatibility layers.
- Avoid redundant validation and excessive assertions.
- Keep changes scoped and commit complete, reviewable changes.
- Do not modify F:/Workspace/7zplus or F:/Workspace/cardo from this project.

## Engineering Conventions

- All new or modified dialogs, menus, tooltips and notifications must follow the Popup UI Standard below and reuse the shared popup components. Do not create independent dialog chrome or perform business operations in render.

- Product copy belongs in locales/zh-CN.ftl, zh-TW.ftl and en-US.ftl. Keep semantic keys and parameter names aligned. Use complete locale messages for variable text.
- Reuse `cardo-runtime` for atomic settings storage, Fluent catalogs and diagnostics. Missing configuration is distinct from unreadable or malformed configuration. Propagate I/O and parsing failures with path context; log error chains without command arguments or passwords. Native dialog failures must report the failure and cancel related work rather than silently rehost business forms.
- Do not use translated labels as state, identifiers or branching conditions. Use enums for domain and platform actions.
- Keep archive operations independent of GPUI and registry code. Platform modules emit commands; ui/system.rs dispatches them into the workspace.
- Explorer commands receive the complete IShellItemArray. Keep the Explorer DLL independent of GPUI and the 7z.exe adapter; share only action definitions, format routing and request data through p7z-commands.
- Context menus must use the clicked target and a selection snapshot. Unavailable operations are omitted; do not clear a multi-selection merely because a background or keyboard menu was opened.
- Use GPUI Kit's matching reexports, Entity/WeakEntity, owned subscriptions, Root and component focus/menu APIs. Consult the pinned dependency sources before copying newer examples.
- Do not perform filesystem, network, registry or process operations during render. Read metadata and run archive work in the background, then update entities.
- Reuse the established project SVG icon assets with provenance and licenses. Preserve their recognizable object shapes and color assignments; do not replace familiar objects with abstract geometric symbols without user approval. The browser page icon reuses the application logo. Inspect artwork at 48px in light and dark themes.
- Product scope is all user-facing functionality of the pinned 7-Zip 26.03 File Manager, presented through the existing GPUI layout. The user explicitly superseded earlier exclusions of filesystem management, viewing/editing and benchmarks. Implement real behavior and format-specific availability; do not substitute launching 7zFM for integrated application functionality or label incomplete coverage as complete.
- Keep the capability scope and gaps in README.md and README.zh.md aligned with the official File/Edit/View/Favorites/Tools/Help commands, toolbar operations, option pages, format-dependent dialogs, keyboard shortcuts and Windows integration. UI, context menus and shortcuts must share operations and selection semantics.
- Registry changes must be explicit and limited to the application's own per-user keys and values. Do not replace the user's default archive association.
- Use `cardo-runtime::registry` for ownership checks and idempotent removal. Configuration must not overwrite another installation; uninstall must retain conflicting identities. Keep product registry paths and association policy in the platform crate. Apply GPUI color tokens through `cardo-ui::theme`, keeping product palette choices and persistence outside that crate.
- Resolve font stacks through `cardo-ui::fonts` before saving or applying them. Report missing families at the input; never silently replace an explicitly configured family. Keep installed glyph fallback families in the user's order.
- Do not fabricate progress, data, successful results or claims of visual parity. Document source implementation separately from runtime evidence.
- Maintain architecture, shared UI conventions, verification limits and known gaps in README.md and README.zh.md when behavior changes. Keep asset provenance and licensing in THIRD_PARTY.md.

## Popup UI Standard

- Preserve Home's established action styling and transparent history-row removal controls. Settings-control restyling must not redesign Home or change its centered Open/Create and history layout without a specific request.

- Text action buttons use persistent neutral backgrounds, including disabled states. Icon-only controls and large artwork tools remain transparent at rest, as do inactive page/segmented tabs. Do not apply text-button fills to navigation icons. Scrolling checkbox pickers reuse `cardo-ui::settings::picker_list`, whose 20px right gutter keeps item backgrounds and checks clear of the pinned 16px overlay scrollbar. Preserve separate menu-row, file-row and native window-chrome semantics.

- Reuse `cardo-ui::settings` for settings rows, outlined groups, actions, switches, radio segments, selectors, steppers, inputs and searchable checkbox pickers. Setting names are semibold; descriptions wrap in regular muted text. Pick controls by purpose: a read-only path with native picker for directories, a validated input for font stacks and an explicit-save textarea for extraction patterns. Product modules own values, localization, validation and persistence. Home has centered side-by-side Open/Create actions above at most eight archive history entries, without a left brand column or large logo.

- `cardo-ui::panel` owns dialog frames, headers, bodies, fields, information cards and action bars. `cardo-ui::metrics::popup` owns dimensions; the theme palette owns semantic colors. Compose `panel_layout`, one `panel_body` or `panel_document`, and `panel_actions`. Editors may own their scrolling. Never nest scroll owners, cards or independent dialog shells.
- Dialogs and subpages share an outer background and inset content surface. Dialog titles and the left identity rail use the background; body and action bar share the content surface. Keep the 44px title, 20px body padding, 16px section gaps, 13px body text and 32px controls.
- Reuse `panel_surface` for inset content in the main window and dialogs; keep its inset padding so rectangular child backgrounds do not cover rounded corners. Settings pages share the main window and horizontal labeled icon navigation. Create inputs in the main window, preserve drafts and update results across page switches, and block switching or closing while saving.
- `h_flex()` centers children vertically by default. Side-by-side navigation/content layouts must use `items_stretch()` and fill the remaining height with `flex_1().min_h_0()` below fixed headers. Do not rely on a child's percentage height to size an auto-height parent.
- `PanelSize` and `dialogs/state.rs` own semantic sizing. Defaults should contain ordinary forms without scrolling. Limit against the display's visible area, not the owner content area's height. Center over the measured owner panel, then clamp to display edges. Titles and action bars remain visible when long content scrolls.
- Use cards only for information summaries, properties, comparison metadata, results or technical details. Use ordinary aligned fields for forms. Paths use `path_strip`; prose wraps and long reports scroll. Flex text containers require `min_w_0`. No long label or path may displace a close button or action outside the window.
- Actions use specific verbs, secondary actions first and one main action last. Use `panel_danger` for destructive operations. Dismiss using the top-right Close control or Escape; do not duplicate Close in the footer. Form Cancel and task Stop remain explicit. Validation stays beside the relevant field. Use `menu_choice` for themed selectors with a persistent border and background. Use `choice_menu` for wider right-aligned popups anchored to compact triggers; ordinary command menus keep independent widths. The main content panel reserves 12px above its frame for the connected notch. File associations use a persistent searchable checkbox popover, a selected-count summary, alphabetic ordering, right-side checks, without All/None/Invert action buttons. Search and options share one scroll owner so the right scrollbar spans the popup's top and bottom insets. A bounded scrollbar is appropriate for this multi-select picker, not for command menus.
- `dialogs/prompt.rs` owns native window lifecycle, focus and dismissal; action modules own submission and cleanup. Close, Cancel and Escape share cleanup. Backdrop clicks must not discard forms. Progress offers Stop rather than dismissing a running operation. Complete and cancel paths release both dialog state and native handles before another result appears. Results with paths or follow-up actions belong in movable dialogs, not notifications. Native file pickers remain OS surfaces.
- Command menus, including File and context menus, use cardo-ui Menu, MenuItem and MenuTrigger backed by the pinned GPUI Kit NativeMenu. Keep callbacks bound to the originating window and menu generation, and defer business work until entity borrows are released. Preserve selection snapshots, keyboard navigation, shortcuts and checked/disabled states. Windows owns native cascade and screen-edge placement. Settings selectors remain themed PopupMenu surfaces; use owned PopoverState and Positioner for searchable multiselect and history. History keeps its measured address width and paged rows. Settings triggers hug content; dropdown menus are wider, right aligned and viewport bounded. The active selector trigger toggles its menu closed without reopening on release. Scrolling outside the menu dismisses it without consuming the page scroll; scrolling inside the association picker keeps it open. Multiselect scroll areas require explicit bounded height. OS file pickers and Explorer integration remain native.
- Sorting and selection belong in shared-width file-table headers; the path bar owns navigation and refresh. Main-toolbar navigation uses visible labels and horizontal icons on the right: the application logo for the shared file/archive browser, then Application, System, Advanced and About. Appearance controls belong to an Application section. About includes updates; no separate Help or Updates entry, no extra Compress tool and no independent settings window. File > Settings / Ctrl+, also selects Application. All four subpages use settings_page, settings_content and `cardo-ui::settings::group` on the same inset white surface: the full available panel width with the scrollbar at the right panel edge, 24px titles aligned with section headings and a Back button in a reserved gutter to their left, transparent 20px rounded group outlines, inset separators, labels left and controls right. Use semantic dark equivalents; no nested cards, shadows or independent dialog footers. Create settings inputs in the main window and preserve drafts/update results across page switches. Reuse window_grip in draggable headers. Folder/archive navigation shares one browser. Draw the active tab notch and content frame as a single filled/stroked path so their junction has no internal border.
- Tooltips reuse cardo-ui::tooltip::bubble_tooltip, inverse colors, 14px radius, 10px horizontal and 4px vertical padding, 12px text with 18px line height (26px single-line height), a 360px maximum width and viewport clamping. Keep the rounded background outside the inset text scroll owner. They contain no commands and never resize triggers. Use action hints only for icon-only controls or artwork tools with hidden labels, and supplemental explanations on deliberate information icons. Complete visible labels, normal descriptions, window controls and the titlebar grip have no redundant tooltips. Text labels, paths, menu entries and labeled buttons expose full-text hints only when GPUI actually truncates their shaped text; do not use character-count estimates or unconditional tooltip wrappers. Notifications remain brief passive messages at the content panel's bottom center; allow dragging, reset position for each new message and expire after three seconds. Actionable errors and operation results use dialogs.
- The connected tab indicator slides to the measured active icon center with a 200ms ease-out transition. First layout snaps into place; rapid page changes retarget from the current interpolated position. Respect reduced motion and stop requesting frames when settled. Keep the notch and panel outline as one path throughout the transition.
- Review every changed Modal variant, all three locales, selection snapshots, availability, input focus and cancellation. Use pinned dependency APIs and owned subscriptions. After an authorized build, inspect representative dialog sizes, menu boundaries, long text, themes, languages and scaling. Report observed coverage separately from source conclusions; do not claim exhaustive verification.

- Long text uses `cardo-ui::text::compact_text` for constrained labels with a full-text tooltip only when truncated, and `body_text` for wrapping descriptions, settings labels, validation and prose. File names and read-only paths use middle ellipsis; never shorten stored values to fit UI. Toolbar labels stay at 11px with two 13px lines and ellipsis; never shrink fonts to fit translations. Buttons/selectors use the shared command controls with bounded width, ellipsis and full labels. Checkboxes use the shared wrapping-label constructor with explicit accessibility names. Protect icons, close buttons and actions from flex shrink. Editable inputs retain cursor scrolling, and technical reports retain complete copyable text with their document scroll owner. Tooltip width and height must fit the viewport; oversized passive text can be read by hovering the tooltip and scrolling. Do not infer runtime coverage from compilation.
